# Publishing plugins

A release is the exact tested artifact plus metadata that lets administrators evaluate compatibility, install it, upgrade it, and recover from failure.

## Artifact

- Build from a clean checkout with the project wrapper.
- Test the final shaded/relocated JAR.
- Inspect that `plugin.yml`, licenses, and required resources are present.
- Publish a checksum and keep immutable release artifacts.

## Versioning and compatibility

- Use a consistent version scheme and changelog.
- List tested Minecraft/server and Java versions.
- Call out breaking configuration, data, command, permission, or API changes.
- Provide migration and rollback instructions before shipping irreversible formats.

## Documentation

- Explain installation, required/optional dependencies, permissions, commands, configuration, and data storage.
- Include support channels and a minimal diagnostic checklist.
- Disclose metrics, network access, update checks, and collected data.
- Choose a license for your code and comply with bundled dependency licenses.

## Review checklist

- The feature has one clear lifecycle owner.
- Failure paths are observable and preserve valid previous state.
- Resource, queue, cache, and loop bounds are explicit.
- The final built JAR is tested on every claimed server line.
