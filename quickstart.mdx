This guide walks you through every step needed to go from an empty directory to a running Bukkit plugin on a local Minecraft server. You will set up a Maven project, write a minimal `JavaPlugin` subclass, define a `plugin.yml` descriptor, build a JAR, and verify that your plugin loads correctly.

<Tip>
  Keep a local SpigotMC or PaperMC test server handy before you begin. You will need a running server to verify the plugin loads in the final steps. Never test new plugins directly on a production server.
</Tip>

<Steps>

  <Step title="Add the Bukkit dependency">
    The Bukkit API artifact lives in the SpigotMC Maven snapshot repository. Add the repository declaration and the dependency to your `pom.xml`. Use `provided` scope so Maven compiles against the API without bundling it in your JAR — the server already ships the implementation at runtime.

    <CodeGroup>

    ```xml pom.xml
    <repositories>
        <repository>
            <id>spigotmc-repo</id>
            <url>https://hub.spigotmc.org/nexus/content/repositories/snapshots/</url>
        </repository>
    </repositories>

    <dependencies>
        <dependency>
            <groupId>org.bukkit</groupId>
            <artifactId>bukkit</artifactId>
            <version>26.2-R0.1-SNAPSHOT</version>
            <scope>provided</scope>
        </dependency>
    </dependencies>
    ```

    ```groovy build.gradle
    repositories {
        maven {
            url 'https://hub.spigotmc.org/nexus/content/repositories/snapshots/'
        }
    }

    dependencies {
        compileOnly 'org.bukkit:bukkit:26.2-R0.1-SNAPSHOT'
    }
    ```

    </CodeGroup>

    Also confirm your compiler target is Java 17. In Maven, add the compiler plugin to `<build>`:

    ```xml pom.xml (compiler plugin)
    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.11.0</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
    ```
  </Step>

  <Step title="Create your plugin main class">
    Every Bukkit plugin needs one class that extends `org.bukkit.plugin.java.JavaPlugin`. The server instantiates this class when it loads your plugin and calls `onEnable()` immediately after. Create the file at the path matching your package:

    ```java src/main/java/com/example/myplugin/MyPlugin.java
    package com.example.myplugin;

    import org.bukkit.plugin.java.JavaPlugin;

    public class MyPlugin extends JavaPlugin {

        @Override
        public void onEnable() {
            getLogger().info("MyPlugin has been enabled!");
        }

        @Override
        public void onDisable() {
            getLogger().info("MyPlugin has been disabled.");
        }
    }
    ```

    - `onEnable()` runs when the server loads your plugin. Use it to register event listeners, commands, and scheduled tasks.
    - `onDisable()` runs when the server shuts down or unloads your plugin. Use it to flush any data you need to persist.
    - `getLogger()` returns a `java.util.logging.Logger` scoped to your plugin's name. Prefer it over `System.out.println`.
  </Step>

  <Step title="Create plugin.yml">
    Place a `plugin.yml` file at `src/main/resources/plugin.yml`. The server reads this file from the root of your JAR to identify your plugin before loading any classes. The three required fields are `name`, `version`, and `main`.

    ```yaml src/main/resources/plugin.yml
    name: MyPlugin
    version: 1.0.0
    main: com.example.myplugin.MyPlugin
    api-version: '1.21'
    description: My first Bukkit plugin
    author: YourName
    ```

    The `api-version` field tells the server which Bukkit API version your plugin was written against, which helps the server apply the correct compatibility behavior. See the [plugin.yml reference](/plugin-yml) for every available field.
  </Step>

  <Step title="Build with Maven">
    Run the standard Maven lifecycle from your project root to compile the code and package it into a JAR:

    ```bash Terminal
    mvn clean package
    ```

    Maven places the finished JAR in `target/`. It will be named something like `myplugin-1.0.0.jar` based on your `<artifactId>` and `<version>` settings in `pom.xml`.
  </Step>

  <Step title="Install into your server">
    Copy the JAR from `target/` into the `plugins/` directory of your test server, then restart the server:

    ```bash Terminal
    cp target/myplugin-1.0.0.jar /path/to/your/server/plugins/
    ```

    Then start (or restart) the server:

    ```bash Terminal
    java -jar server.jar nogui
    ```

    The server scans the `plugins/` directory on every startup and loads all valid plugin JARs it finds.
  </Step>

  <Step title="Verify the plugin loaded">
    Watch the server console output during startup. You should see your plugin's enable message appear in the log:

    ```text Console output
    [12:00:01 INFO]: [MyPlugin] Enabling MyPlugin v1.0.0
    [12:00:01 INFO]: [MyPlugin] MyPlugin has been enabled!
    ```

    You can also confirm the plugin is active by typing `/plugins` in the server console or in-game. Your plugin's name appears highlighted in green when it has loaded successfully.

    If the plugin name appears in red or is missing entirely, check the console for earlier error messages — they usually point directly to a misconfigured `plugin.yml` or a missing class.
  </Step>

</Steps>
