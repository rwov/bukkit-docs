`plugin.yml` is your plugin's manifest file. The server reads it directly from the root of your JAR before it loads any of your classes. It tells the server your plugin's name, entry-point class, version, dependencies, commands, and permissions. Omitting required fields or placing the file anywhere other than the JAR root will cause the server to reject your plugin entirely at startup.

## Required fields

You must include all three of the following fields in every `plugin.yml`. Missing any one of them will throw an exception and cause the server to skip your plugin.

| Field | Type | Description |
| --- | --- | --- |
| `name` | String | The unique identifier for your plugin. Must contain only alphanumeric characters, underscores, hyphens, and periods (`a–z A–Z 0–9 _ - .`). Spaces are deprecated. Used as the data-folder name and referenced by other plugins in `depend`/`softdepend`. |
| `version` | String | An arbitrary version string, typically `MAJOR.MINOR.PATCH` (e.g. `1.4.1`). Displayed in `/version <PluginName>` output. |
| `main` | String | The fully qualified class name of your `JavaPlugin` subclass (e.g. `com.example.myplugin.MyPlugin`). Must not start with `org.bukkit.`. |

<ParamField path="name" type="string" required>
  The unique name of your plugin. Case-sensitive. Used for the data folder, dependency resolution, and log prefixing. Must match the regex `^[A-Za-z0-9 _.-]+$` — any other character causes a load failure.

  ```yaml plugin.yml
  name: MyPlugin
  ```
</ParamField>

<ParamField path="version" type="string" required>
  The plugin's version string. No specific format is enforced, but `MAJOR.MINOR.PATCH` (e.g. `1.4.1`) is conventional. Shown in `/version MyPlugin` output.

  ```yaml plugin.yml
  version: 1.4.1
  ```
</ParamField>

<ParamField path="main" type="string" required>
  The fully qualified name of the class that extends `JavaPlugin`. The class loader uses this to instantiate your plugin. The package must not begin with `org.bukkit.`.

  ```yaml plugin.yml
  main: com.example.myplugin.MyPlugin
  ```
</ParamField>

## Common optional fields

<ParamField path="description" type="string">
  A human-readable summary of what your plugin does. Supports multiple lines. Displayed in `/version <PluginName>` output.

  ```yaml plugin.yml
  description: Adds custom crafting recipes and economy features.
  ```
</ParamField>

<ParamField path="author" type="string">
  The primary author's name or forum handle. Displayed in `/version <PluginName>` output and included in server error messages so administrators know who to contact. Use `authors` (list) when there are multiple authors.

  ```yaml plugin.yml
  author: YourName
  ```
</ParamField>

<ParamField path="authors" type="list of strings">
  A YAML list of author names. When both `author` and `authors` are specified, the single `author` value is prepended to the list as the lead developer.

  ```yaml plugin.yml
  authors: [Alice, Bob, Carol]
  ```
</ParamField>

<ParamField path="contributors" type="list of strings">
  A YAML list of contributors who helped with the plugin but are not primary authors. Unlike `authors`, contributors are not mentioned in server error messages.

  ```yaml plugin.yml
  contributors: [Dave, Eve]
  ```
</ParamField>

<ParamField path="website" type="string">
  A URL to your plugin's documentation, SpigotMC resource page, or repository. Displayed in `/version <PluginName>` output.

  ```yaml plugin.yml
  website: https://www.spigotmc.org/resources/myplugin.12345/
  ```
</ParamField>

<ParamField path="api-version" type="string">
  The Bukkit API version your plugin targets (e.g. `'1.21'`). The server uses this to apply appropriate compatibility handling. Omitting it may trigger a legacy-mode warning on modern servers. Quote the value in YAML to avoid it being parsed as a float.

  ```yaml plugin.yml
  api-version: '1.21'
  ```
</ParamField>

<ParamField path="load" type="string">
  Controls which phase of server startup your plugin loads during. Accepted values:

  - `POSTWORLD` _(default)_ — Your plugin loads after the worlds have been loaded. This is correct for the vast majority of plugins.
  - `STARTUP` — Your plugin loads before worlds are loaded. Use this only when you need to affect world generation or very early server initialization.

  ```yaml plugin.yml
  load: STARTUP
  ```
</ParamField>

<ParamField path="prefix" type="string">
  A custom string to prefix all log messages produced by `getLogger()`. Defaults to the plugin's `name` when not set.

  ```yaml plugin.yml
  prefix: AwesomePlugin
  ```
</ParamField>

<ParamField path="depend" type="list of strings">
  A YAML list of plugin names that must be present and loaded before your plugin can load. If any plugin in this list is missing, your plugin will fail to load. Reference plugins by their `name` field value.

  ```yaml plugin.yml
  depend:
    - Vault
    - WorldEdit
  ```
</ParamField>

<ParamField path="softdepend" type="list of strings">
  A YAML list of plugin names that your plugin can work with but does not strictly require. The server loads soft-dependencies before your plugin when they are present but will not prevent your plugin from loading if they are absent.

  ```yaml plugin.yml
  softdepend:
    - PlaceholderAPI
  ```
</ParamField>

<ParamField path="loadbefore" type="list of strings">
  A YAML list of plugin names that should treat your plugin as their soft-dependency. This is the inverse of `softdepend`: your plugin will be loaded before each plugin named here, without requiring those plugins to list you explicitly.

  ```yaml plugin.yml
  loadbefore:
    - SomeOtherPlugin
  ```
</ParamField>

<ParamField path="provides" type="list of strings">
  A YAML list of API names that your plugin implements or replaces. Other plugins may declare a `depend` or `softdepend` on one of these names instead of your plugin's actual `name`. Useful for drop-in replacements or when publishing an API surface under a stable alias.

  ```yaml plugin.yml
  provides:
    - EconomyAPI
    - LegacyEconomy
  ```
</ParamField>

<ParamField path="libraries" type="list of strings">
  A list of Maven GAV coordinates (`groupId:artifactId:version`) to download from Maven Central and add to your plugin's classpath at runtime. This is a preview feature — check your server version's support before relying on it.

  ```yaml plugin.yml
  libraries:
    - com.squareup.okhttp3:okhttp:4.9.0
  ```
</ParamField>

<ParamField path="default-permission" type="string">
  The fallback default state for all permissions registered by this plugin that do not specify their own `default`. Accepted values: `op`, `not op`, `true`, `false`. Defaults to `op` when not set.

  ```yaml plugin.yml
  default-permission: op
  ```
</ParamField>

## Defining commands

Add a `commands` block to register slash-commands with the server at load time. Each command name maps to a set of optional properties. You must still implement the command logic in Java using `CommandExecutor`, but declaring the command here is what makes `/yourcommand` available on the server.

```yaml plugin.yml (commands block)
commands:
  greet:
    description: Greet a player by name.
    aliases: [hello, hi]
    permission: myplugin.greet
    permission-message: You don't have permission to use /greet.
    usage: /greet <player>
  stats:
    description: Display your play statistics.
    permission: myplugin.stats
    usage: /stats [player]
```

| Command property | Type | Description |
| --- | --- | --- |
| `description` | String | A user-friendly explanation of what the command does. Shown in `/help` output. |
| `aliases` | String or list | Alternative names for the command. Aliases can only be defined here — setting them at runtime has no effect. Must not contain a colon. |
| `permission` | String | The permission node required to execute the command. Players without it receive the `permission-message` and the executor is never called. |
| `permission-message` | String | The message shown to players who lack the required permission. Use `<permission>` as a placeholder for the permission node name. |
| `usage` | String | The message sent to the player when the `CommandExecutor` returns `false`. Use `<command>` as a placeholder for the command name actually typed. |

<Warning>
  Command names and aliases must not contain a colon (`:`). Including one will prevent the plugin from loading.
</Warning>

## Defining permissions

Add a `permissions` block to register permission nodes with the server when your plugin loads. Declaring permissions here lets server administrators manage them in permission plugins and lets you set sensible defaults.

```yaml plugin.yml (permissions block)
permissions:
  myplugin.*:
    description: Grants all MyPlugin permissions.
    default: op
    children:
      myplugin.greet: true
      myplugin.stats: true
      myplugin.admin: true
  myplugin.greet:
    description: Allows the player to use /greet.
    default: true
  myplugin.stats:
    description: Allows the player to view statistics.
    default: true
  myplugin.admin:
    description: Allows access to administrative commands.
    default: op
```

The `default` value for each permission node controls who has it without an explicit grant from a permissions plugin:

| Value | Who has the permission by default |
| --- | --- |
| `true` | Every player on the server |
| `false` | Nobody (must be granted explicitly) |
| `op` | Only server operators |
| `not op` | Everyone who is **not** an operator |

Use `children` to build a permission hierarchy. When a parent permission is granted, all children mapped to `true` are also granted. This lets you create a single wildcard node (e.g. `myplugin.*`) that covers every feature permission.

## Full plugin.yml example

The following example shows all common fields together for a realistic plugin:

```yaml plugin.yml
# ── Required ────────────────────────────────────────────────────────────────
name: Inferno
version: 1.4.1
main: com.example.inferno.Inferno

# ── Identity ────────────────────────────────────────────────────────────────
description: Set yourself (and others) on fire. Adds fire-based commands and events.
author: CaptainInflamo
authors: [Cogito, verrier]
contributors: [Choco, md_5]
website: https://www.spigotmc.org/resources/inferno.99999/
prefix: Inferno

# ── API compatibility ────────────────────────────────────────────────────────
api-version: '1.21'

# ── Load order ───────────────────────────────────────────────────────────────
load: POSTWORLD
depend:
  - NewFire
  - FlameWire
softdepend:
  - PlaceholderAPI
loadbefore:
  - FireLogger
provides:
  - Hell

# ── Runtime libraries ────────────────────────────────────────────────────────
libraries:
  - com.squareup.okhttp3:okhttp:4.9.0

# ── Commands ─────────────────────────────────────────────────────────────────
commands:
  flagrate:
    description: Set yourself on fire.
    aliases: [combust_me, combustMe]
    permission: inferno.flagrate
    permission-message: You do not have /<permission>
    usage: /flagrate
  burningdeaths:
    description: List how many times you have died by fire.
    aliases: [burning_deaths, burningDeaths]
    permission: inferno.burningdeaths
    usage: /burningdeaths [player]

# ── Permissions ───────────────────────────────────────────────────────────────
default-permission: op

permissions:
  inferno.*:
    description: Gives access to all Inferno commands.
    default: op
    children:
      inferno.flagrate: true
      inferno.burningdeaths: true
      inferno.burningdeaths.others: true
  inferno.flagrate:
    description: Allows you to ignite yourself.
    default: true
  inferno.burningdeaths:
    description: Allows you to see how many times you have burned to death.
    default: true
  inferno.burningdeaths.others:
    description: Allows you to see how many times others have burned to death.
    default: op
    children:
      inferno.burningdeaths: true
```
