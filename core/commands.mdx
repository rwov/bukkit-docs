# Commands

A Bukkit command starts with an untrusted sender and string arguments. Parse into a typed request, authorize it, execute domain logic, and return a useful result.

## Declare and register

- Declare the command in `plugin.yml`.
- Resolve it with `getCommand`; treat `null` as a packaging/configuration error.
- Attach a `CommandExecutor` and optionally a `TabCompleter`.
- Return `false` only when Bukkit should send the declared usage string.

## Sender and arguments

- A sender may be a player, console, command block, or remote console.
- Check `sender instanceof Player` only for player-only behavior.
- Validate argument count before indexing the array.
- Parse numbers, UUIDs, materials, and enum-like values with targeted error messages.

## Completion

- Suggest only values valid at the current argument position.
- Filter by the partially typed prefix.
- Do not perform blocking database or network calls from tab completion.
- Do not leak hidden player names, admin options, or unauthorized resources.

## Example

```java
public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
    if (!sender.hasPermission("example.give")) return true;
    if (args.length != 1) {
        sender.sendMessage("Usage: /" + label + " <amount>");
        return true;
    }
    try {
        int amount = Integer.parseInt(args[0]);
        if (amount < 1 || amount > 64) throw new NumberFormatException();
        // Apply the authorized action.
    } catch (NumberFormatException ex) {
        sender.sendMessage("Amount must be from 1 to 64.");
    }
    return true;
}
```

## Production check

- Validate inputs and capabilities before mutation.
- Keep hot-path work bounded and observable.
- Re-check live state after any delay or asynchronous boundary.
- Clean up every resource owned by the feature during disable.
