# Services manager

`ServicesManager` is an in-process registry for interfaces supplied by plugins. Consumers depend on the interface contract while providers choose the implementation.

## Publish a service

- Put the public interface in a small stable API artifact or documented package.
- Register the implementation during enable with a `ServicePriority`.
- Document thread expectations, nullability, errors, and lifecycle.
- Unregister the provider during disable.

## Consume a service

- Declare a hard or soft plugin relationship when load order matters.
- Call `load(Interface.class)` and handle `null` for optional capabilities.
- Do not cache a provider forever if providers can change; listen for service register/unregister events when dynamic replacement matters.
- Never cast to another plugin's private implementation.

## Compatibility

- Version the API contract independently when appropriate.
- Add methods compatibly or publish a new interface for breaking changes.
- Keep Bukkit objects out of long-lived cross-plugin data contracts where stable IDs suffice.
- Fail with a targeted message when a required provider is absent or incompatible.

## Example

```java
ServicesManager services = getServer().getServicesManager();
services.register(EconomyApi.class, economy, this, ServicePriority.Normal);

RegisteredServiceProvider<EconomyApi> registration =
    services.getRegistration(EconomyApi.class);
if (registration == null) {
    getLogger().warning("No EconomyApi provider is available");
} else {
    EconomyApi api = registration.getProvider();
}
```

## Production check

- Validate inputs and capabilities before mutation.
- Keep hot-path work bounded and observable.
- Re-check live state after any delay or asynchronous boundary.
- Clean up every resource owned by the feature during disable.
