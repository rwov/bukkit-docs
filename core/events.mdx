# Events and listeners

Events report server activity to registered listeners. A handler observes or modifies the event currently being dispatched; it should not assume it is the only plugin involved.

## Register handlers

- Implement `Listener` and annotate handler methods with `@EventHandler`.
- Register the listener through `PluginManager#registerEvents` during enable.
- Use the most specific event type and return early when the event is irrelevant.
- Bukkit removes a disabled plugin's registered listeners, but feature-level shutdown can use `HandlerList.unregisterAll(listener)`.

## Priority and cancellation

- Priorities run from `LOWEST` through `MONITOR`; use them to coordinate intent, not to win conflicts.
- Use `ignoreCancelled = true` when your handler should not process an action another plugin rejected.
- Only observe at `MONITOR`; do not change the event there.
- Cancellation is event-specific and does not always mean the underlying action is completely reversible.

## Async events

- Check the event contract or `Event#isAsynchronous()`.
- Do not access ordinary live Bukkit state from an asynchronous handler unless that API explicitly permits it.
- Copy plain data, perform isolated work, then schedule live mutations onto the main thread.

## Example

```java
public final class BlockPolicyListener implements Listener {
    @EventHandler(priority = EventPriority.HIGH, ignoreCancelled = true)
    public void onBreak(BlockBreakEvent event) {
        if (!event.getPlayer().hasPermission("example.break")) {
            event.setCancelled(true);
            event.getPlayer().sendMessage("You cannot break blocks here.");
        }
    }
}
```

## Production check

- Validate inputs and capabilities before mutation.
- Keep hot-path work bounded and observable.
- Re-check live state after any delay or asynchronous boundary.
- Clean up every resource owned by the feature during disable.
