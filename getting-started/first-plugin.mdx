# Your first plugin

The smallest useful plugin has one entry class, valid metadata, a reproducible build, and an observable enable/disable cycle.

## Create the entry point

- Extend `JavaPlugin`; do not construct this class yourself.
- Use `onEnable()` to validate configuration and register behavior.
- Use `onDisable()` to cancel owned work and flush data.
- Log meaningful state, not a decorative startup banner.

## Declare the plugin

- Set `name`, `version`, and fully qualified `main` in `plugin.yml`.
- Add `api-version` matching the oldest API behavior you target.
- Declare commands and permissions before resolving them in code.
- Keep the metadata file at the root of the built JAR.

## Build and run

- Package with Maven or Gradle.
- Copy the JAR into the test server's `plugins/` directory.
- Start the server and confirm the enable log contains no stack trace.
- Stop the server normally and confirm disable completes cleanly.

## Minimal implementation

```java
public final class ExamplePlugin extends JavaPlugin {
    @Override
    public void onEnable() {
        getLogger().info("ExamplePlugin enabled");
    }

    @Override
    public void onDisable() {
        getLogger().info("ExamplePlugin disabled");
    }
}
```

```yaml
name: ExamplePlugin
version: 1.0.0
main: com.example.plugin.ExamplePlugin
api-version: '1.21'
```

## Done check

Test the final JAR through a clean server start and stop. Treat warnings and shutdown failures as defects, not harmless development noise.
