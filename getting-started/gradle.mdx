# Gradle setup

A Gradle plugin project needs a Java toolchain, the Spigot snapshots repository, a `compileOnly` API dependency, and resources packaged into the JAR.

## Core configuration

- Apply the `java` plugin.
- Use `java { toolchain { languageVersion = JavaLanguageVersion.of(...) } }`.
- Declare the Spigot API with `compileOnly`.
- Keep dependency versions in one place so upgrades are intentional.

## Resources and metadata

- Place `plugin.yml` under `src/main/resources`.
- Use `processResources` only when values such as the project version must be expanded.
- Declare every expanded token as an input so Gradle caching remains correct.
- Inspect `build/libs/` after `./gradlew clean build`.

## Bundled libraries

- Use Shadow only for libraries that must ship inside the plugin.
- Relocate packages where another plugin might bundle a conflicting version.
- Exclude signatures and server APIs from the shaded artifact.
- Test the final shaded JAR, not only the thin development JAR.

## Example

```kotlin
plugins { java }

repositories {
    maven("https://hub.spigotmc.org/nexus/content/repositories/snapshots/")
}

dependencies {
    compileOnly("org.spigotmc:spigot-api:YOUR_TARGET_VERSION-R0.1-SNAPSHOT")
}

java {
    toolchain.languageVersion.set(JavaLanguageVersion.of(YOUR_JAVA_VERSION))
}
```

## Done check

Verify the built artifact from a clean build and test it through a full server start and stop. Record the exact Java, server, and plugin versions when behavior differs between environments.
