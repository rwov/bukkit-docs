# Java and tools

Use a JDK version supported by the Minecraft server you target, not merely the version installed by your operating system. Keep compilation, local testing, and production on deliberately chosen versions.

## Required tools

- A full JDK, verified with `java -version` and `javac -version`.
- IntelliJ IDEA, Eclipse, VS Code, or another Java-aware editor.
- Maven Wrapper or Gradle Wrapper committed with the project.
- A separate local Spigot-compatible server directory for destructive testing.

## Verify the toolchain

- Run `./mvnw -version` or `./gradlew --version` and confirm the reported JVM.
- Set the compiler release or Gradle toolchain explicitly.
- Build from the terminal once; an IDE-only build can hide missing configuration.
- Start the test server from its own directory so relative paths and plugin data stay isolated.

## Version discipline

- Compiling with a newer bytecode target than the server JVM produces `UnsupportedClassVersionError`.
- Compiling against APIs newer than the running server can produce `NoSuchMethodError` or `NoClassDefFoundError`.
- Do not add server implementation JARs as ordinary bundled dependencies.
- Record the tested server build, Java version, and plugin version in bug reports.

## Done check

Verify the built artifact from a clean build and test it through a full server start and stop. Record the exact Java, server, and plugin versions when behavior differs between environments.
