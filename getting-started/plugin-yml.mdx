# plugin.yml reference

`plugin.yml` is parsed before your plugin enables. Invalid metadata can prevent the entry class from loading, so treat it as part of the executable contract.

## Required identity

- `name` is the human-readable plugin name.
- `version` identifies the artifact; build tooling may expand it.
- `main` is the fully qualified `JavaPlugin` subclass.
- `api-version` opts into modern material and API behavior for the declared release.

## Commands and permissions

- Each command key can define `description`, `usage`, `aliases`, and `permission`.
- Permission entries can define `description`, `default`, and `children`.
- A declared permission does not replace runtime authorization checks.
- Keep command names lowercase and avoid collisions with common server commands.

## Load relationships

- `depend` requires another plugin and orders this plugin after it.
- `softdepend` changes order when the other plugin exists but does not require it.
- `loadbefore` asks Bukkit to load this plugin before named optional consumers.
- Still check capabilities at runtime because metadata alone does not guarantee a compatible API.

## Complete shape

```yaml
name: ExamplePlugin
version: 1.0.0
main: com.example.plugin.ExamplePlugin
api-version: '1.21'
authors: [YourName]
commands:
  example:
    description: Runs the example command
    usage: /example <value>
    permission: example.use
permissions:
  example.use:
    description: Allows /example
    default: true
softdepend: [Vault]
```

## Done check

Test the final JAR through a clean server start and stop. Treat warnings and shutdown failures as defects, not harmless development noise.
