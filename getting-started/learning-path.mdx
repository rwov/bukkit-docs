# Complete learning path

Learn plugin development in layers. Each stage below has a concrete exit test; move on when you can complete it without copying a full project.

## 1. Java and builds

- Be comfortable with classes, interfaces, collections, exceptions, generics, and try-with-resources.
- Create a Maven or Gradle project that compiles against the Spigot API.
- Exit test: build a JAR repeatedly from a clean checkout.

## 2. Lifecycle, commands, and events

- Implement a minimal `JavaPlugin`, declare it in `plugin.yml`, and verify enable/disable logs.
- Register a command with sender validation and tab completion.
- Register listeners and understand cancellation, priority, and synchronous versus asynchronous events.
- Exit test: a command changes behavior and an event handler can be cleanly disabled.

## 3. Game state and persistence

- Work with players, locations, worlds, blocks, entities, inventories, and `ItemMeta`.
- Use UUIDs and `NamespacedKey` for durable identity.
- Move configuration, database, and HTTP work behind small repository interfaces.
- Exit test: data survives restart and a disconnected player does not leave stale state.

## 4. Production engineering

- Profile tick-time problems before optimizing.
- Test domain logic separately and exercise the built JAR on a real server.
- Design explicit startup, failure, reload, and shutdown behavior.
- Exit test: the plugin handles missing config, dependency failure, reload, and shutdown without data loss.

## Done check

Verify the built artifact from a clean build and test it through a full server start and stop. Record the exact Java, server, and plugin versions when behavior differs between environments.
