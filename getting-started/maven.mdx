# Maven setup

Maven should download the Spigot API for compilation, keep it out of the final JAR, compile with a fixed Java release, and copy resources such as `plugin.yml` unchanged.

## Minimal `pom.xml`

- Use the Spigot snapshots repository over HTTPS.
- Declare `spigot-api` with `provided` scope because the server supplies it.
- Set `maven.compiler.release` to the Java version supported by the target server.
- Keep `plugin.yml` in `src/main/resources`.

## Dependency scope

- Use `provided` for server APIs.
- Use normal compile scope for libraries you intentionally shade into the plugin.
- Relocate shaded libraries when class-name collisions are plausible.
- Never shade Bukkit, Spigot API, or the server implementation into the plugin.

## Build and inspect

- Run `./mvnw clean package`.
- Open the JAR or run `jar tf target/*.jar` and confirm `plugin.yml` is present.
- Confirm Bukkit classes are absent from the JAR.
- Install the artifact from `target/` into the local server's `plugins/` directory.

## Example

```xml
<repositories>
  <repository>
    <id>spigot-repo</id>
    <url>https://hub.spigotmc.org/nexus/content/repositories/snapshots/</url>
  </repository>
</repositories>
<dependencies>
  <dependency>
    <groupId>org.spigotmc</groupId>
    <artifactId>spigot-api</artifactId>
    <version>YOUR_TARGET_VERSION-R0.1-SNAPSHOT</version>
    <scope>provided</scope>
  </dependency>
</dependencies>
```

<Note>
  Replace the placeholder with the exact API version you test. Do not silently float to a different Minecraft release.
</Note>

## Done check

Verify the built artifact from a clean build and test it through a full server start and stop. Record the exact Java, server, and plugin versions when behavior differs between environments.
