# Debugging plugins

Start with the first relevant exception, not the last line printed. Capture the complete server log, identify the plugin version and server build, and reproduce from a clean restart.

## Read a stack trace

- The exception type describes the failure category.
- The message usually names the missing class, invalid value, or rejected operation.
- The first stack frame in your package is the best initial breakpoint.
- A `Caused by` chain often contains the actual root cause.

## Common startup failures

- `InvalidPluginException`: wrong `main`, missing class, invalid bytecode, or constructor/load failure.
- `UnknownDependencyException`: a required `depend` plugin is absent.
- `NoClassDefFoundError`: a library was not bundled or a server API is unavailable.
- YAML parse errors: indentation, tabs, quoting, or invalid scalar structure in metadata/config.

## Runtime diagnosis

- Reproduce with exact steps and known inputs.
- Add structured debug logging around state transitions, identifiers, and timings.
- Check whether the call occurred on the main thread and whether the object is still valid.
- Minimize the failing case before blaming an API.

## Done check

Test the final JAR through a clean server start and stop. Treat warnings and shutdown failures as defects, not harmless development noise.
