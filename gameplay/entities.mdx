# Entities and mobs

An `Entity` is live world state with a UUID, location, type, validity, passengers, and persistent data. `LivingEntity`, `Mob`, projectiles, displays, and vehicles add specialized behavior.

## Spawn and identify

- Spawn with `World#spawn` or `spawnEntity` on the main thread.
- Configure the entity in the spawn consumer when the overload supports it, before other code observes it.
- Tag plugin-owned entities with `PersistentDataContainer` and a `NamespacedKey`.
- Store UUIDs for later resolution rather than long-lived entity references.

## Query and mutate

- Use bounded nearby-entity queries and filter by type, tag, validity, and ownership.
- Check `isValid` and `isDead` before delayed mutations.
- Use teleport, velocity, AI, target, equipment, and attribute APIs only for compatible entity types.
- Respect spawn, damage, targeting, death, and removal events from other plugins.

## Cleanup

- Remove temporary entities when their feature or world ends.
- Handle chunk unload and plugin disable.
- Do not repeatedly scan every entity in every world.
- Avoid assuming a stored UUID still resolves after restart.

## Example

```java
Zombie zombie = world.spawn(location, Zombie.class, mob -> {
    mob.setCustomName("Arena Guard");
    mob.setRemoveWhenFarAway(false);
    mob.getPersistentDataContainer().set(kindKey, PersistentDataType.STRING, "guard");
});
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
