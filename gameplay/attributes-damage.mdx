# Attributes and damage

Attributes define numeric capabilities such as max health or movement speed. Damage is an event-driven operation influenced by armor, effects, invulnerability, difficulty, and other plugins.

## Attributes

- Resolve an `AttributeInstance` and handle `null` when an entity does not support it.
- Use a stable namespaced modifier identity where the API provides keyed modifiers.
- Choose ADD\_NUMBER, ADD\_SCALAR, or MULTIPLY\_SCALAR\_1 deliberately.
- Remove or replace plugin-owned modifiers instead of stacking duplicates after reload.

## Health

- Keep health within `0..maxHealth`.
- Changing max health may require clamping current health.
- Use absorption separately from base health.
- Do not use health as durable identity or persistent progression storage.

## Damage events

- Observe or cancel the appropriate damage event before applying side effects.
- At `MONITOR`, observe only and respect cancellation.
- Avoid recursive calls to `damage` from a damage handler without a guard.
- Use the modern damage-source APIs available on the target version when attribution matters.

## Example

```java
AttributeInstance speed = mob.getAttribute(Attribute.MOVEMENT_SPEED);
if (speed != null) {
    speed.getModifiers().stream()
        .filter(modifier -> modifier.getName().equals("example:arena_speed"))
        .forEach(speed::removeModifier);
    speed.addModifier(arenaSpeedModifier);
}
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
