# BlockData

`BlockData` describes a material plus typed block-state properties such as facing, waterlogging, power, age, or slab type. It is separate from tile data stored by `BlockState`.

## Create and parse

- Obtain default data from a material or parse a serialized block-data string through Bukkit.
- Check specialized interfaces such as `Directional`, `Openable`, `Ageable`, or `Waterlogged`.
- Clone data before mutating a value shared by your own cache.
- Reject user/config strings that cannot be parsed.

## Compare and transform

- `matches` can compare whether explicitly specified states are compatible.
- Use `rotate` and `mirror` for structure placement instead of manually rewriting every facing.
- Not every block implements every property interface.
- Apply the final data with an explicit physics choice.

## Example

```java
BlockData data = Material.OAK_STAIRS.createBlockData();
if (data instanceof Directional directional) {
    directional.setFacing(BlockFace.NORTH);
}
block.setBlockData(data, false);
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
