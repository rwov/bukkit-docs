# Boss bars

A `BossBar` is a mutable server object with a title, color, style, progress, flags, visibility, and explicit player membership.

## Create and update

- Use an ordinary boss bar for runtime UI or a keyed boss bar when registry-style lookup is required.
- Clamp progress to `0.0..1.0`.
- Update only when title, progress, or phase actually changes.
- Add and remove players as session membership changes.

## Lifecycle

- One shared bar suits one shared encounter; per-player bars suit private state.
- Hide or remove all players when the feature ends.
- Cancel the task that updates the bar.
- Do not create a new bar every tick or leave keyed bars registered after their owner disables.

## Example

```java
BossBar bar = Bukkit.createBossBar("Round ends", BarColor.BLUE, BarStyle.SEGMENTED_10);
bar.addPlayer(player);
bar.setProgress(Math.max(0.0, Math.min(1.0, remaining / (double) total)));
// On cleanup:
bar.removeAll();
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
