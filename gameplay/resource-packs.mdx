# Resource packs

A server resource pack is an external asset download offered to a client. The URL, cryptographic hash, prompt, required flag, and client status are part of one delivery workflow.

## Prepare the pack

- Host a valid ZIP over HTTPS with stable availability.
- Generate the exact hash required by the overload you use and update it whenever bytes change.
- Version asset URLs or filenames to avoid stale caches.
- Keep vanilla-compatible fallbacks for players who decline or fail.

## Send and observe

- Send the pack from the main thread to the intended player.
- Explain what the pack changes and whether it is required.
- Handle `PlayerResourcePackStatusEvent` for accepted, downloaded, declined, and failed outcomes.
- Do not grant pack-dependent rewards merely because a request was sent.

## Example

```java
@EventHandler
public void onPackStatus(PlayerResourcePackStatusEvent event) {
    switch (event.getStatus()) {
        case SUCCESSFULLY_LOADED -> enablePackFeatures(event.getPlayer());
        case DECLINED, FAILED_DOWNLOAD -> useVanillaFallback(event.getPlayer());
        default -> { }
    }
}
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
