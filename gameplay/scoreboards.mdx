# Scoreboards and teams

A scoreboard owns objectives and teams. Players see either the main scoreboard or a custom scoreboard assigned to them; changing assignment can conflict with other plugins.

## Objectives

- Create an objective with a unique internal name and display slot.
- Use stable unique entries for sidebar rows; duplicate visible text needs distinct hidden entries.
- Update changed scores and labels instead of recreating the entire board.
- Unregister objectives no longer owned by the feature.

## Teams

- Teams can format entries and control collision, friendly fire, and name-tag visibility.
- An entry belongs to at most one team on a scoreboard.
- Use prefixes and suffixes within client limits and preserve other plugins' ownership.
- Prefer a shared scoreboard coordinator when multiple features need the same player scoreboard.

## Example

```java
Scoreboard board = Bukkit.getScoreboardManager().getNewScoreboard();
Objective objective = board.registerNewObjective("status", Criteria.DUMMY, "Match");
objective.setDisplaySlot(DisplaySlot.SIDEBAR);
objective.getScore("Players").setScore(onlineCount);
player.setScoreboard(board);
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
