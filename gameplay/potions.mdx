# Potion effects

A `PotionEffect` is a value containing type, duration in ticks, amplifier, ambient state, particles, and icon visibility. Applying one may replace or be rejected by an existing effect.

## Create effects

- Amplifier zero means level I; one means level II.
- Use tick durations for gameplay effects and guard against overflow for long values.
- Choose ambient, particle, and icon flags according to whether players need feedback.
- Use infinite duration only when lifecycle cleanup is guaranteed.

## Apply and compare

- Check the current effect when replacement policy matters.
- Decide whether stronger, longer, or any new effect should win.
- `addPotionEffect` returns whether the entity's active state changed.
- Remove only effects your feature intends to own; other plugins may use the same vanilla type.

## Lifecycle

- Reapply persistent domain effects after respawn if required.
- Clear temporary effects when a match or session ends.
- Handle milk, death, beacons, commands, and other plugins changing the same effect.
- Do not refresh every tick when a longer duration with periodic reconciliation works.

## Example

```java
PotionEffect current = player.getPotionEffect(PotionEffectType.SPEED);
PotionEffect proposed = new PotionEffect(PotionEffectType.SPEED, 20 * 10, 1, false, true, true);
if (current == null || current.getAmplifier() <= proposed.getAmplifier()) {
    player.addPotionEffect(proposed, true);
}
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
