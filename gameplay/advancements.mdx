# Advancements

Bukkit exposes loaded advancements and per-player progress. Completion is criterion-based: an advancement is complete only when all required criteria groups are satisfied by the underlying definition.

## Find advancements

- Resolve by `NamespacedKey` and handle missing or data-pack-disabled entries.
- Iterate all advancements only for infrequent administrative work.
- Do not hard-code assumptions about custom data-pack advancements.
- Store keys as strings when configuration needs to reference them.

## Progress

- Use `Player#getAdvancementProgress`.
- Inspect remaining and awarded criteria.
- Grant or revoke individual criterion names returned by the progress object.
- Do not invent criterion names or assume granting one always completes the advancement.

## Bulk operations

- Bound grant/revoke loops and run them on the main thread.
- Report partial failures when a data pack changes mid-operation.
- Avoid regranting unchanged criteria every tick.
- Test after data-pack reloads and server upgrades.

## Example

```java
Advancement advancement = Bukkit.getAdvancement(key);
if (advancement == null) return;
AdvancementProgress progress = player.getAdvancementProgress(advancement);
for (String criterion : List.copyOf(progress.getRemainingCriteria())) {
    progress.awardCriteria(criterion);
}
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
