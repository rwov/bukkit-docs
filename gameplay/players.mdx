# Players and OfflinePlayer

`Player` represents an online connection and live entity. `OfflinePlayer` is an identity-oriented view that may never have joined and does not provide live world or inventory state.

## Identity

- Store `UUID`, not player names, as the durable key.
- Resolve an online player with `Bukkit.getPlayer(uuid)` at the moment of use.
- `Bukkit.getOfflinePlayer(uuid)` does not guarantee cached profile data or an online session.
- Treat display names, list names, and profile names as mutable presentation.

## Session lifecycle

- Create session state on join only after required data is available.
- Remove references on quit and kick; persist by UUID.
- After async work, re-resolve the player and verify the session generation is still current.
- Do not keep `Player` objects in static collections across disable or reconnect.

## Example

```java
UUID id = commandTargetId;
Player target = Bukkit.getPlayer(id);
if (target == null || !target.isOnline()) {
    sender.sendMessage("That player is not online.");
    return;
}
target.sendMessage("You have a pending request.");
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
