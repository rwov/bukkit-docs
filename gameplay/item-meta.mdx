# ItemMeta and components

`ItemMeta` holds the mutable metadata for a stack. Some materials expose specialized meta such as `SkullMeta`, `PotionMeta`, or `BookMeta`; modern versions also expose component-style data.

## Read-modify-write

- Get meta from the stack, check the specialized type, mutate it, then call `setItemMeta`.
- A meta object is not applied merely because you changed it.
- Clone shared item templates before customization.
- Use namespaced persistent data for plugin identity instead of display-name matching.

## Presentation and behavior

- Treat display name and lore as player-visible text, not authorization.
- Validate enchantments, attribute modifiers, model identifiers, trims, food, tool, weapon, and consumable components against the target API.
- Use stable namespaced keys for plugin-owned cooldown groups and custom data.
- Provide vanilla fallback behavior when a resource pack or component is unavailable.

## Compatibility

- Component APIs evolve across Minecraft releases; compile and run against the exact supported set.
- Do not cast to specialized meta without `instanceof`.
- Remove only modifiers or data owned by your plugin.
- Test serialization and item migration across plugin upgrades.

## Example

```java
ItemStack item = new ItemStack(Material.DIAMOND);
ItemMeta meta = item.getItemMeta();
meta.setDisplayName("Recall Crystal");
meta.getPersistentDataContainer().set(itemKindKey, PersistentDataType.STRING, "recall");
item.setItemMeta(meta);
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
