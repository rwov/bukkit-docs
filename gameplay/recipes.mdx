# Recipes and crafting

Static recipes are registered under a `NamespacedKey`. Dynamic rules belong in preparation/craft events, where every matrix and result must be treated as untrusted current state.

## Register recipes

- Use a unique `NamespacedKey` owned by the plugin.
- Choose shaped, shapeless, cooking, stonecutting, smithing, or complex recipe APIs based on the mechanic.
- Define exact ingredients with `RecipeChoice` where appropriate.
- Register during enable and remove plugin-owned keys during disable when needed.

## Dynamic validation

- Use `PrepareItemCraftEvent` to calculate or clear a preview result.
- Use `CraftItemEvent` to authorize the final action and account for shift-click crafting.
- Identify custom ingredients with PDC or exact controlled metadata, not only display names.
- Recompute from the current matrix; do not trust an earlier preview.

## Duplication safety

- Handle remaining items, container items, stack sizes, and full inventories.
- Bound looped shift-click results.
- Make rewards transactional when crafting affects external balances.
- Test recipe discovery and conflicts with data packs and other plugins.

## Example

```java
NamespacedKey key = new NamespacedKey(plugin, "recall_crystal");
ShapedRecipe recipe = new ShapedRecipe(key, result);
recipe.shape(" E ", "EDE", " E ");
recipe.setIngredient('E', Material.ENDER_PEARL);
recipe.setIngredient('D', Material.DIAMOND);
Bukkit.addRecipe(recipe);
```

## Production checklist

- Validate the current object type, ownership, and lifecycle before mutation.
- Bound hot-path loops and spatial work.
- Respect cancellation and changes made by other plugins.
- Remove plugin-owned runtime state during feature shutdown.
