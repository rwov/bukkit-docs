# Chat, titles, and action bars

Choose the smallest message surface that matches the urgency and lifetime of the information. Chat persists, action bars are transient, and titles interrupt the center of the screen.

## Select a channel

- Use chat for commands, explanations, and information players may need to scroll back to.
- Use an action bar for rapidly changing status such as cooldowns or progress.
- Use titles sparingly for major state transitions; pair them with sound or chat only when needed.
- Console and non-player senders require plain command feedback rather than player-only UI.

## Message hygiene

- Build messages from trusted templates and escaped player-controlled values.
- Rate-limit repeated warnings and deduplicate unchanged action-bar content.
- Keep localization keys separate from business logic.
- Do not rely on color alone to convey success, warning, or failure.

## Example

```java
player.sendMessage("Kit selected: " + safeKitName);
player.sendActionBar("Cooldown: " + remainingSeconds + "s");
player.sendTitle("Round starting", "Prepare to fight", 10, 40, 10);
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
