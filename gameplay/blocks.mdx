# Blocks and BlockState

`Block` is a live coordinate view into a world. `BlockState` captures state for a block at a moment and must be explicitly updated when edits should reach the world.

## Live block access

- Resolve blocks from a loaded world and integer coordinates.
- Use `setType` or `setBlockData` for direct material/state changes.
- Choose whether physics should run based on the operation and API overload.
- Never read or mutate live blocks from an arbitrary async thread.

## BlockState

- Call `getState()` and check the specific state type such as `Container`, `Sign`, or `CreatureSpawner`.
- Edit the state object, then call `update` when required.
- A saved snapshot can become stale if another plugin or player changes the block.
- Verify the current material/state before applying delayed edits.

## Large edits

- Bound the region and validate world borders and height.
- Batch changes across ticks to protect tick time.
- Decide rollback and physics behavior before starting.
- Do not retain thousands of live `Block` objects when coordinates suffice.

## Example

```java
Block block = world.getBlockAt(x, y, z);
if (block.getState() instanceof Sign sign) {
    sign.setLine(0, "Welcome");
    sign.update(true, false);
}
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
