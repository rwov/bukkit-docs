# Sounds and particles

Sounds and particles are client feedback emitted from a world position or directly to selected players. Scope recipients and effect count to the gameplay meaning.

## Sounds

- Use world playback when nearby players should hear the same event.
- Use player playback for private UI feedback.
- Choose category, volume, and pitch deliberately; large volume expands the audible radius.
- Stop long-running sounds when their session ends.

## Particles

- Send a small count for directional or point effects; a count of zero has special directional behavior for some particles.
- Match particle data to the particle type, such as dust options, items, or blocks.
- Precompute shapes as relative vectors, then translate to the live location.
- Reduce density with distance and avoid spawning large clouds every tick.

## Example

```java
Location at = player.getLocation().add(0, 1, 0);
player.playSound(at, Sound.BLOCK_NOTE_BLOCK_PLING, 0.8f, 1.4f);
player.spawnParticle(Particle.HAPPY_VILLAGER, at, 8, 0.3, 0.4, 0.3, 0.0);
```

## Production checklist

- Validate identity, world, and feature ownership at the point of mutation.
- Keep main-thread work bounded; move only isolated data work off-thread.
- Handle disconnect, unload, reload, and disable explicitly.
- Read the exact API contract for the server version you target.
