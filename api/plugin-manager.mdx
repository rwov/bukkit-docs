`PluginManager` is the central hub for inter-plugin coordination on a Bukkit server. You access it at any point after your plugin is loaded via `getServer().getPluginManager()`, or through the static shorthand `Bukkit.getPluginManager()`. From it you can wire up event listeners, fire events, declare and query permissions, and inspect the state of every other plugin running on the server.

## Registering Events

### `registerEvents(Listener, Plugin)`

```java
public void registerEvents(@NotNull Listener listener, @NotNull Plugin plugin)
```

Scans the given `Listener` instance for all methods annotated with `@EventHandler` and registers each one with the server's event bus. This is the method you call in `onEnable()` for every listener class your plugin provides. Pass `this` as the `Plugin` argument so Bukkit knows which plugin owns the registrations and can clean them up if the plugin is disabled.

```java title="Registering listeners in onEnable()"
@Override
public void onEnable() {
    PluginManager pm = getServer().getPluginManager();
    pm.registerEvents(new PlayerJoinListener(), this);
    pm.registerEvents(new BlockBreakListener(), this);
    pm.registerEvents(new InventoryListener(), this);
}
```

<Tip>
  You do not need to unregister listeners manually on shutdown. Bukkit
  unregisters all handlers belonging to a plugin automatically when that plugin
  is disabled.
</Tip>

### `registerEvent(Class, Listener, EventPriority, EventExecutor, Plugin)`

```java
public void registerEvent(
    @NotNull Class<? extends Event> event,
    @NotNull Listener listener,
    @NotNull EventPriority priority,
    @NotNull EventExecutor executor,
    @NotNull Plugin plugin
)
```

Registers a single event type with an explicit `EventExecutor` and priority. Use this lower-level overload when you need to register handlers dynamically at runtime — for example, when the event class is not known at compile time or when you are building a framework that forwards events programmatically.

### `registerEvent(Class, Listener, EventPriority, EventExecutor, Plugin, boolean)`

```java
public void registerEvent(
    @NotNull Class<? extends Event> event,
    @NotNull Listener listener,
    @NotNull EventPriority priority,
    @NotNull EventExecutor executor,
    @NotNull Plugin plugin,
    boolean ignoreCancelled
)
```

Same as the five-argument form, but the `ignoreCancelled` flag controls whether your executor is invoked when the event has already been cancelled by an earlier handler. Set `ignoreCancelled` to `true` to skip cancelled events and avoid redundant processing.

<Note>
  For typical plugin development, prefer `registerEvents()` with `@EventHandler`
  annotations over the manual `registerEvent()` overloads. The annotation-based
  API is safer, more readable, and handles priority via the annotation's
  `priority` attribute.
</Note>

## Calling Events

### `callEvent(Event)`

```java
public void callEvent(@NotNull Event event) throws IllegalStateException
```

Dispatches the given event to every registered handler in priority order. All handlers execute synchronously before `callEvent()` returns, so you can inspect the event's state immediately after the call — including whether it was cancelled or had its values modified by another plugin's handler.

```java title="Firing a custom cancellable event"
PlayerArenaJoinEvent event = new PlayerArenaJoinEvent(player, arena);
getServer().getPluginManager().callEvent(event);

if (event.isCancelled()) {
    player.sendMessage("Another plugin prevented you from joining the arena.");
    return;
}

// Safe to proceed — no handler cancelled the event
arena.addPlayer(player);
```

<Warning>
  Calling an asynchronous event from the main server thread (or a synchronous
  event from an async thread) throws `IllegalStateException`. Always fire async
  events from async tasks and synchronous events from the main thread.
</Warning>

## Permissions

### `addPermission(Permission)`

```java
public void addPermission(@NotNull Permission perm)
```

Registers a `Permission` object with the server so that permission-checking code, other plugins, and permission management plugins can resolve it by name. Bukkit automatically registers permissions declared in `plugin.yml` when your plugin loads; call this method only when you need to register permissions dynamically at runtime.

Throws `IllegalArgumentException` if a permission with the same name is already registered.

```java title="Registering a dynamic permission"
Permission perm = new Permission(
    "myplugin.arena." + arena.getName(),
    "Access to arena " + arena.getName(),
    PermissionDefault.OP
);
getServer().getPluginManager().addPermission(perm);
```

### `removePermission(Permission)`

```java
public void removePermission(@NotNull Permission perm)
```

Removes a previously registered `Permission` from the server's permission registry. If the permission is not registered, the call is silently ignored.

<Warning>
  Removing a permission does **not** revoke it from players or other
  `Permissible` objects that currently have it. Those entities retain the
  permission value they already calculated until they recalculate.
</Warning>

### `removePermission(String)`

```java
public void removePermission(@NotNull String name)
```

Overload that looks up and removes the permission by its fully-qualified name string rather than requiring you to hold the `Permission` object.

### `getPermission(String)`

```java
@Nullable
public Permission getPermission(@NotNull String name)
```

Returns the `Permission` registered under the given fully-qualified name, or `null` if no such permission exists. Use this to inspect another plugin's registered permissions or to check whether a permission you are about to add is already present.

```java title="Checking before adding a permission"
PluginManager pm = getServer().getPluginManager();
if (pm.getPermission("myplugin.admin") == null) {
    pm.addPermission(new Permission("myplugin.admin", PermissionDefault.OP));
}
```

### `getPermissions()`

```java
@NotNull
public Set<Permission> getPermissions()
```

Returns a snapshot copy of all currently registered `Permission` objects across every loaded plugin. The returned `Set` is independent — changes to it do not affect the live registry. Iterate it to enumerate server-wide permissions, for example when building a permission listing tool.

### `getDefaultPermissions(boolean op)`

```java
@NotNull
public Set<Permission> getDefaultPermissions(boolean op)
```

Returns the set of permissions that are granted by default to players (`op = false`) or operators (`op = true`). Useful when you need to programmatically inspect which permissions a fresh, non-operator player holds without examining any player object.

## Plugin Inspection

### `getPlugin(String)`

```java
@Nullable
public Plugin getPlugin(@NotNull String name)
```

Returns the loaded `Plugin` instance with the given name, or `null` if no plugin with that name is currently loaded. Plugin names are **case-sensitive** and must match the `name` field in the target plugin's `plugin.yml`.

```java title="Obtaining a reference to another plugin"
Plugin vaultPlugin = getServer().getPluginManager().getPlugin("Vault");
if (vaultPlugin != null) {
    // Cast to Vault's API class and use it
}
```

### `getPlugins()`

```java
@NotNull
public Plugin[] getPlugins()
```

Returns an array of all currently loaded plugins. The order is not guaranteed. Iterate this when you need to enumerate every plugin on the server — for example, to build a plugin list command or to scan for plugins that implement a particular interface.

```java title="Listing all loaded plugin names"
for (Plugin plugin : getServer().getPluginManager().getPlugins()) {
    getLogger().info(plugin.getName() + " v" + plugin.getDescription().getVersion());
}
```

### `isPluginEnabled(String)`

```java
public boolean isPluginEnabled(@NotNull String name)
```

Returns `true` if a plugin with the given name is both loaded and currently enabled. This is the idiomatic check to perform before you attempt to use another plugin's API.

```java title="Guarding optional integration code"
if (getServer().getPluginManager().isPluginEnabled("PlaceholderAPI")) {
    PlaceholderAPI.registerExpansion(new MyExpansion(this));
}
```

### `isPluginEnabled(Plugin)`

```java
@Contract("null -> false")
public boolean isPluginEnabled(@Nullable Plugin plugin)
```

Returns `true` if the given `Plugin` instance is currently enabled, `false` for `null` or a disabled plugin. Prefer this form when you already hold a `Plugin` reference.

## Disabling Plugins

### `disablePlugin(Plugin)`

```java
public void disablePlugin(@NotNull Plugin plugin)
```

Disables the specified plugin: calls its `onDisable()`, unregisters its event handlers and commands, and cancels its scheduled tasks. Attempting to disable an already-disabled plugin has no effect.

<Warning>
  Disabling plugins at runtime from within another plugin is **strongly
  discouraged** in most cases. It can leave the server in an inconsistent state
  if the disabled plugin held resources or data that other plugins depend on.
  This method is primarily intended for administration or plugin management
  tools, not for ordinary inter-plugin logic.
</Warning>

### `enablePlugin(Plugin)`

```java
public void enablePlugin(@NotNull Plugin plugin)
```

Enables a loaded-but-disabled plugin by calling its `onEnable()`. Like `disablePlugin()`, this is intended for administrative tooling. Normal plugin-to-plugin interaction should not rely on manually toggling enabled state.

## Code Examples

### Register listeners in `onEnable()`

```java title="MyPlugin.java — full onEnable() setup"
@Override
public void onEnable() {
    PluginManager pm = getServer().getPluginManager();

    // Register all listener classes
    pm.registerEvents(new PlayerListener(this), this);
    pm.registerEvents(new WorldListener(this), this);

    // Register a runtime permission not declared in plugin.yml
    pm.addPermission(new Permission(
        "myplugin.feature.beta",
        "Access to beta features",
        PermissionDefault.FALSE
    ));

    getLogger().info("Listeners and permissions registered.");
}
```

### Fire a custom event and check cancellation

```java title="Firing a custom cancellable event"
// Define your event class (must extend Event, implement Cancellable if needed)
PlayerEnterZoneEvent zoneEvent = new PlayerEnterZoneEvent(player, zone);
Bukkit.getPluginManager().callEvent(zoneEvent);

if (zoneEvent.isCancelled()) {
    // Another plugin vetoed the entry — respect it
    player.sendMessage(ChatColor.RED + "You cannot enter this zone.");
    return;
}

zone.onPlayerEnter(player);
```

### Check whether another plugin is loaded

```java title="Conditional integration with a soft dependency"
PluginManager pm = getServer().getPluginManager();

// isPluginEnabled() is the correct guard — covers both missing and disabled cases
if (pm.isPluginEnabled("Vault")) {
    getLogger().info("Vault found — enabling economy features.");
    hookVault();
} else {
    getLogger().warning("Vault not found — economy features disabled.");
}
```
